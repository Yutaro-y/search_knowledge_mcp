# search-knowledge-mcp 仕様書

## 1. 概要
`search-knowledge-mcp` は、OpenAI Responses API + Web Search を利用し、ネットワーク機器・OS・ライブラリ・SDK・CVE・既知バグ・リリースノートなどの最新技術情報を収集して MCP ツールとして提供する Python 製サーバです。

検索結果の URL だけでなく、必要に応じて検索結果ページ本文も取得し、本文から要点・コマンド候補・手順候補・注意点を抽出したうえで、クライアント AI が扱いやすい構造化 JSON を返します。

## 2. 目的
- 最新の公式ドキュメントやベンダー情報を優先して取得する
- LangChain / LangGraph などの MCP クライアントから扱いやすい構造化 JSON を返す
- URL 本文由来の補足情報も返し、クライアント AI が根拠付きで回答しやすい状態を作る
- GitHub / PyPI 公開を見据えた Python パッケージ構成を維持する

## 3. アーキテクチャ
- Transport: stdio
- MCP 実装: FastMCP
- 言語: Python 3.11+
- パッケージ管理: uv
- 検索基盤: OpenAI Responses API + `web_search_preview`
- 設定管理: `pydantic-settings` + `.env`
- HTTP本文取得: `httpx`
- 入出力検証: Pydantic v2

## 5. モジュール構成と役割
### 5.1 `server.py`
- FastMCP の初期化
- MCP ツール定義
- `main()` による stdio サーバ起動

### 5.2 `config.py`
- `.env` / 環境変数読み込み
- OpenAI 接続設定、既定言語、検索件数、鮮度条件、ログレベルなどの一元管理

### 5.3 `schemas.py`
- MCP ツール入力スキーマ
- 検索結果レスポンススキーマ
- テキスト正規化を含む返却直前の整形

### 5.4 `clients/openai_client.py`
- OpenAI Responses API 呼び出し
- Web Search 実行
- 検索結果の構造化
- 必要に応じた URL 本文取得・補強処理

### 5.5 `clients/fetch_client.py`
- URL への HTTP GET
- charset / meta charset / apparent encoding を考慮したデコード
- `page_fetch_status` の判定

### 5.6 `search/query_builder.py`
- ベンダー・機種・カテゴリを加味した複数検索クエリ生成
- 一部ベンダー向け `site:` ヒント付与

### 5.7 `search/parser.py`
- OpenAI Responses API の返却から URL・タイトル・スニペットを抽出
- annotations 優先、本文 URL フォールバック対応
- URL 単位の重複排除

### 5.8 `search/classifier.py`
- URL / タイトル / スニペットから以下を推定
  - `source_type`
  - `content_kind`
  - `categories`
  - `trust_level_hint`

### 5.9 `search/content_extractor.py`
- HTML から script/style やタグを除去してプレーンテキスト化
- 返却用テキストの空白・改行正規化

### 5.10 `search/page_analyzer.py`
- URL 本文から以下を雑にでも構造化
  - `extracted_facts`
  - `possible_commands`
  - `possible_procedures`
  - `important_notes`
  - `source_excerpt`
  - `page_content_summary`
  - `recommended_usage`

## 6. 提供ツール
### 6.1 `search_network_knowledge`
統合検索ツール。ネットワーク機器・OS・CVE・リリースノートなどを横断検索する。

入力:
- `query`
- `device_vendor`
- `device_model`
- `os_version`
- `categories`
- `max_results`
- `language`
- `freshness_days`
- `include_page_content`（既定値: `true`）

出力:
- `query`
- `normalized_query`
- `results[]`
- `fetched_at`
- `notes_for_llm`
- `error`

### 6.2 用途別ラッパツール
- `search_network_docs`
  - ネットワーク機器のコマンドリファレンス・設定例・公式ドキュメント向け
- `search_os_and_software_specs`
  - OS / ライブラリ / SDK の仕様・制約・設定例向け
- `search_vulnerabilities_and_bugs`
  - CVE / 既知バグ / 回避策 / 修正版情報向け
- `search_release_notes_and_updates`
  - リリースノート / 更新情報 / 仕様変更向け
- `search_freeform_tech_info`
  - 上記に収まらない自由形式の技術情報向け

## 8. 検索処理フロー
1. MCP ツール入力を Pydantic で検証する
2. `query_builder.py` で複数検索クエリ候補を生成する
3. `openai_client.py` で OpenAI Responses API + Web Search を実行する
4. `parser.py` で URL、タイトル、スニペット、CVE、バージョン手掛かりなどを抽出する
5. `classifier.py` で `source_type` / `content_kind` / `categories` / `trust_level_hint` を補完する
6. `include_page_content=true` の場合は検索結果 URL を `fetch_client.py` で取得する
7. `content_extractor.py` で HTML から可読テキストを抽出する
8. `page_analyzer.py` で本文から要点・コマンド候補・手順候補・注意点を構造化する
9. `schemas.py` により返却前テキストを正規化し、MCP クライアントへ JSON を返す

`.env.example` で定義されている主な設定項目は以下の通り。

### 9.1 必須

### 9.2 任意

- `DEFAULT_LANGUAGE`
- `DEFAULT_MAX_RESULTS`
- `DEFAULT_FRESHNESS_DAYS`

- `LOG_LEVEL`

## 10. 設計上のポイント
- 公式ドメイン優先のクエリを生成する
- URL を含む構造化レスポンスを重視する
- クライアント AI が信頼判断しやすいよう、`source_type` だけでなく `content_kind` / `trust_signals` / `trust_level_hint` を返す
- OpenAI API 側のレスポンス差異に備え、annotations / プレーンテキスト URL の両方に対応する
- `include_page_content` を既定 ON にし、検索結果 URL の本文補強を優先する
- OpenAI API キーをログに出さない前提の実装とする

## 11. エラー処理
- `OPENAI_API_KEY` 未設定時は例外で停止させず、`error` を含む正常系 JSON を返す
- OpenAI API 呼び出し失敗時も `results=[]` と `notes_for_llm` を返す
- URL 本文取得失敗時は処理全体を止めず、対象結果のみ `page_fetch_status` に状態を残す

## 13. 既知の制約
- 検索品質は OpenAI Responses API / Web Search の返却品質に依存する
- 本文抽出は汎用 HTML 処理であり、JavaScript 依存ページや複雑な DOM では情報を十分に取れない可能性がある
- `page_analyzer.py` の抽出はヒューリスティックであり、厳密な文書理解ではない
- 現時点では URL の厳密な死活確認専用レイヤやキャッシュ層はない
- `source_type` / `content_kind` / `trust_level_hint` は補助情報であり、最終判断は利用側で行う前提
- `src/search_knowledge_mcp/tools/` は未使用であり、将来的な分割余地を残している
