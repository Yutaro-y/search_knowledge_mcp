# 🔧 NW 機器・OS 情報特化型 インターネット検索 MCP サーバ 仕様書（最終版）

## 1. サーバの目的（あなたのユースケースに最適化）
AI エージェントが以下を **高精度で自動判断できる** ようにする：

### 1.1 NW 機器の正確なコマンド構文取得
- Cisco IOS/IOS-XE/IOS-XR/NX-OS  
- YAMAHA RTX/NVR  
- Juniper JunOS  
- Fortinet FortiOS  
- Palo Alto PAN-OS  
などの **公式コマンドリファレンス** を正確に取得。

### 1.2 OS・バージョン依存の設定判断
- OS バージョンごとの仕様差異  
- 非推奨コマンド  
- 新旧構文の違い  
- バージョン固有の制限事項  

### 1.3 バグ情報・CVE・リリースノートを踏まえた構成検討
- Cisco Bug Search  
- Fortinet PSIRT  
- YAMAHA リリースノート  
- CVE / NVD  
- ベンダーの Known Issues  
- Fixed-in バージョン情報  

### 1.4 その他  
- その他最新の情報を取得したいとき。時世も含めて現在利用しているLLMの既存学習内容に完全一致する内容が無い場合など。

これらを **統合的に検索 → 分類 → JSON で返却** し、LangGraph エージェントが「正しい設定案」を生成できるようにする。

# 2. 提供する MCP ツール（最適化版）

## 2.1 メインツール：`search_network_knowledge`

### 🔍 目的  
NW 機器・OS・バージョン・CVE・バグ・リリースノートなど、**構成判断に必要な情報をすべて検索し、分類して返す**。

### 📥 入力スキーマ（最適化）
```json
{
  "query": "string",
  "device_vendor": "string",
  "device_model": "string",
  "os_version": "string",
  "categories": [
    "command_reference",
    "config_example",
    "spec_detail",
    "cve",
    "bug",
    "workaround",
    "release_note",
    "update_info"
  ],
  "max_results": 20,
  "language": "ja | en | auto",
  "freshness_days": 365
}
```

### 📤 出力スキーマ（NW 機器向けに最適化）
```json
{
  "query": "string",
  "normalized_query": "string",
  "results": [
    {
      "title": "string",
      "url": "string",
      "source_type": "official_vendor | security_advisory | documentation | community",
      "categories": ["command_reference", "cve", "release_note"],
      "summary": "string",
      "raw_snippet": "string",
      "metadata": {
        "vendor": "Cisco",
        "product": "IOS-XE",
        "version": "17.9.3",
        "cve_id": "CVE-2024-xxxx",
        "severity": "High",
        "published_date": "2024-01-01T00:00:00Z",
        "fixed_in": "17.9.4"
      },
      "confidence": 0.92
    }
  ],
  "fetched_at": "2026-05-06T10:00:00Z",
  "notes_for_llm": "string"
}
```

# 3. 動作ロジック（NW 機器向けに強化）

## 3.1 クエリ生成（例）
ユーザが「Cisco で OSPF の設定例」と言った場合：

- `Cisco IOS-XE OSPF configuration example`
- `Cisco IOS-XE OSPF command reference`
- `Cisco IOS-XE OSPF bug known issues`
- `Cisco IOS-XE OSPF CVE`
- `Cisco IOS-XE 17.9 release notes OSPF`

**複数クエリを自動生成して並列検索**する。

## 3.2 情報分類ロジック（強化版）
- URL ドメインで分類  
  - `cisco.com` → official_vendor  
  - `nvd.nist.gov` → security_advisory  
  - `community.cisco.com` → community  
- タイトル/本文からカテゴリ推定  
  - “Command Reference” → command_reference  
  - “Configuration Example” → config_example  
  - “CVE-2024” → cve  
  - “Known Issues” → bug  
  - “Fixed in” → workaround  

## 3.3 バージョン依存性の扱い
- `os_version` が指定されている場合：
  - そのバージョンのリリースノートを優先
  - そのバージョンのバグ情報を優先
  - そのバージョンのコマンド構文を優先

## 3.4 再検索ロジック
- 情報が古い場合 → “2025” “latest” を追加して再検索  
- 情報が少ない場合 → ベンダー名を追加  
- バージョンが曖昧 → メジャーバージョンで再検索

# 6. LangGraph / LangChain 連携
クライアントはLangchainのMultiServerMCPClientのget_tools()を利用する。
LangGraph の create_react_agent に tools を渡すだけで利用可能。
stdio方式で接続予定だが、uvxでmcp_configを記載できるようなサーバ実装だと望ましい。

# 7. 「uvx create-mcp-server」を使うべきか？

### ✔ 結論：**使うべき（強く推奨）**。ただ、FastMCP利用でもOK

理由：
- MCP サーバの boilerplate（stdio, handshake, tool 登録）が自動生成される  
- あなたのサーバは **検索ロジックが本体** なので、基盤はテンプレで十分  
- 生成後に `search_network_knowledge` を差し替えるだけでよい  

### 推奨手順
1. `uvx create-mcp-server network-knowledge-mcp`
2. `tools/search_network_knowledge.py` を追加
3. OpenAI 検索ロジックを組み込む
4. JSON スキーマを schemas.py に定義
5. LangGraph から接続して動作確認
