# 🚀 **NW 機器・OS・CVE・リリースノート特化型 インターネット検索 MCP サーバ 仕様書（統合版）**

以下は、**出力1の体系性・MCP準拠性** と **出力2の実用性・NW特化の統合検索能力** を組み合わせた、最終的に最も使いやすく拡張性の高い仕様書です。

# 1. 🎯 サーバの目的（統合版）

AI エージェントが以下を **高精度・高信頼で自動判断できる検索基盤** を提供する：

### 1.1 NW 機器の正確な情報取得
- Cisco / YAMAHA / Fortinet / Juniper / Palo Alto など  
- コマンドリファレンス  
- 設定例  
- OS/バージョン固有の仕様差異  

### 1.2 OS・ミドルウェア・SDK の仕様取得
- Ubuntu / RHEL / Windows Server  
- Python / OpenSSL / systemd / netplan  
- バージョン固有の制限・非推奨項目  

### 1.3 セキュリティ情報の統合取得
- CVE / NVD  
- ベンダー PSIRT  
- Bug Search  
- Known Issues  
- Fixed-in バージョン  

### 1.4 リリースノート・アップデート情報
- 新機能  
- 仕様変更  
- 既知の不具合  
- 重大な変更点  

### 1.5 その他  
- その他最新の情報を取得したいとき。時世も含めて現在利用しているLLMの既存学習内容に完全一致する内容が無い場合など。

# 4. 🔧 提供する MCP ツール（出力2の統合検索 + 出力1の構造化）

## **4.1 メインツール：`search_network_knowledge`（統合版）**

### 🎯 目的  
出力1の「ツールを細分化」する方式と、出力2の「1ツールで統合検索」方式を統合し、  
**1つのツールで NW/OS/CVE/リリースノートを横断検索 → 分類 → 構造化して返す。**

### 📥 入力スキーマ（統合版）
```json
{
  "query": "string",
  "device_vendor": "string",
  "device_model": "string",
  "os_version": "string",
  "categories": [
    "command_reference",
    "config_example",
    "spec_detail",
    "cve",
    "bug",
    "workaround",
    "release_note",
    "update_info"
  ],
  "max_results": 20,
  "language": "auto",
  "freshness_days": 365
}
```

### 📤 出力スキーマ（出力1の構造化 + 出力2の分類）
```json
{
  "query": "string",
  "normalized_query": "string",
  "results": [
    {
      "title": "string",
      "url": "string",
      "source_type": "official_vendor | security_advisory | documentation | community",
      "categories": ["command_reference", "cve", "release_note"],
      "summary": "string",
      "raw_snippet": "string",
      "metadata": {
        "vendor": "string",
        "product": "string",
        "version": "string",
        "cve_id": "string",
        "severity": "string",
        "published_date": "string",
        "fixed_in": "string"
      },
      "confidence": 0.0
    }
  ],
  "fetched_at": "string",
  "notes_for_llm": "string"
}
```

# 5. 🔍 検索ロジック（出力1の体系性 + 出力2の実用性）

## 5.1 クエリ生成（出力2の強化ロジック）
- ベンダー名・OS名・バージョンを自動補完
- カテゴリ別テンプレートを適用
- 例：
  - `"Cisco IOS-XE 17.9 BGP configuration example official documentation"`
  - `"FortiOS 7.4 CVE VPN known issues"`
  - `"Ubuntu 24.04 netplan VLAN config"`

## 5.2 情報分類（出力2の強化ロジック）
- URLドメインで分類
- タイトル・本文からカテゴリ推定
- CVE ID の抽出

## 5.3 レスポンス整形（出力1の構造化）
- summary/snippet を LLM で要約
- metadata を抽出
- confidence スコアを付与

## 5.4 エラー処理（出力1）
- タイムアウト
- リトライ
- JSON-RPC エラーコード

# 8. 🤝 LangGraph / LangChain 連携（出力1 + 出力2）
クライアントはLangchainのMultiServerMCPClientのget_tools()を利用する。
LangGraph の create_react_agent に tools を渡すだけで利用可能。
stdio方式で接続予定だが、uvxでmcp_configを記載できるようなサーバ実装だと望ましい。

エージェント側では：

- 「NW/OS/CVE/リリースノートは必ず MCP ツールで確認」
- 「URL・日付・バージョンを重視」

---

# 9. 🛠 実装手順（出力1の体系性 + 出力2の実用性）

1. `uvx create-mcp-server network-knowledge-mcp`
2. ディレクトリ構成を上記に変更
3. `.env` と `config.py` を実装
4. `schemas.py` に統合スキーマを定義
5. `search_network_knowledge.py` を実装
6. `query_builder` / `classifier` / `parser` を実装
7. `server.py` にツール登録
8. LangGraph から接続して動作確認
